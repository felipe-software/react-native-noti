**Doom uses momentary controls again, and the controls notification retains its original sorting time.** Each movement or Use tap presses its native key for 250 ms; Fire presses for 160 ms. Repeated taps can extend a pulse, and the final tap releases automatically. Pause and Stop release any pending key. The latched-key experiment, checkbox resources, mutable checked-state intents and `controls: 'hold'` API have been removed.

Start the live renderer with `Noti.startDoom({ renderer: 'live' })`. The larger image remains: 815×509 px on the Xiaomi and 817×510 px on the Android 16 emulator. The native engine and GIF encoder library are byte-identical to the size-update release, SHA-256 `9ac88cb8fe423f153c3e431be6b33bf2b5509c4cfa983d827a3a3ceb2aed08b0`.

Two changes address notification ordering:

- Movement, Fire and Use no longer republish the controls card. The removed toggle implementation published checked-state changes after 120 ms to synchronize its collapsed and expanded checkbox instances.
- Both cards now set a stable `Notification.when` for the session. The image has a later session timestamp than the controls. Controls retain theirs when loading finishes, Pause/Resume changes or Sound changes; image heartbeats and paused snapshots also retain the image timestamp.

`setShowWhen(false)` hides the clock but does not freeze the timestamp. A new `Notification.Builder` otherwise supplies a fresh time. AOSP's [NotificationRecord](https://android.googlesource.com/platform/frameworks/base/+/android-14.0.0_r1/services/core/java/com/android/server/notification/NotificationRecord.java) uses a valid developer-provided `when` for time-based ranking, and [NotificationComparator](https://android.googlesource.com/platform/frameworks/base/+/android-14.0.0_r1/services/core/java/com/android/server/notification/NotificationComparator.java) sorts recent times ahead after other ranking criteria. This accounts for the recency change introduced by frequent control updates. Other system ranking criteria remain outside the app's control.

The release was built with R8 and installed on both devices. The one-off UI checks exercise the actual Play button and SystemUI. They inspect the six button types, confirm native pulse-release callbacks have completed for every action and a repeated-tap burst, and compare the image/control accessibility bounds at startup, after each control, after the burst, during Pause, after each Sound change, after the paused-image heartbeat, after Resume and after reopening the shade. The game remained above the controls at every recorded stage. Pause preserved the enlarged image. Stop removed the service. [Structured results](doom-tap-controls-results.json) retain exact bounds and checks.

The native service dump adds `pendingKeyReleases` for this diagnostic; it is not part of the public `DoomStatus` shape. The removed `controls` and `heldControls` status fields belonged to the historical toggle experiment.
